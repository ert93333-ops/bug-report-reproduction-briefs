Bug report reproduction template

Use this checklist before a bug report reaches engineering. It keeps the handoff focused on reproduction steps, expected and actual behavior, environment, impact, severity, evidence, workaround, owner, and follow-up.

Audit sample bug report notes Request early access

Use when the report says

"It is broken", "ASAP", "customer is angry", "I cannot reproduce", or "works on my machine."

Copyable bug reproduction handoff

Title:
[Area] Short symptom written as user-visible behavior

Public-safe symptom:
[What the customer or tester observed]

Reproduction steps:
1. [Exact starting state]
2. [Action]
3. [Action]
4. [Observed failure]

Expected behavior:
[What should happen]

Actual behavior:
[What happened instead]

Environment:
[Browser, device, OS, app version, account tier, region, feature flag, production/staging]

Evidence summary:
[Screenshot, console error, log summary, request id, screen recording, customer quote, or error text summary]

Impact and frequency:
[Who is affected, how often, blocked workflow, revenue/customer risk]

Severity rationale:
[P0/P1/P2/P3 or priority with reason]

Workaround or mitigation:
[Known workaround, retry path, rollback, temporary fix, or none known]

Duplicate or regression context:
[Related issue, recent release, last known good version, component, or regression signal]

Owner and next step:
[Assigned team/person, triage decision, follow-up time, customer reply owner]

Do not include

  • API keys, tokens, passwords, or secrets.
  • Private source code or proprietary logs.
  • Private customer, health, legal, employee, billing, or security details.
  • Compensation, warranty, SLA, or contract promises.

Minimum triage checks

  1. Can another person follow the steps without asking the reporter?
  2. Does the report say expected and actual behavior separately?
  3. Does the environment include enough version/device/context detail?
  4. Does severity explain business or customer impact, not just urgency?
  5. Does the handoff include evidence, workaround, owner, and follow-up decision?
